Welcome to Claude OneClick

This tool routes Claude Code (CLI + VSCode) to a custom model endpoint — DeepSeek, NVIDIA NIMs, OpenRouter, local Ollama, or anything OpenAI-compatible — with a single toggle that applies system-wide.

Takes about 60 seconds to configure. You'll need an API key from your provider.

Step 1 — Pick a provider

Pick the upstream you want Claude Code to talk to. You can change it any time later.

Step 2 — Paste your API key

Paste your provider's API key. It's stored in ~/.config/claude-oneclick/config.json and never leaves your machine except when calling the upstream.

Tip: leave blank to set this later in the General tab.

Step 3 — Flip the toggle

You're set up. Click Finish to apply the env to every shell, VSCode terminal, and Claude Code session.

  • ✓ Active preset set to —
  • ✓ API key saved
  • ✓ Translation proxy will autostart on toggle
  • ✓ CLAUDE_CODE_SKIP_LOGIN=1 will be set so the VSCode extension doesn't ask you to log in

After clicking Finish: open a new terminal or VSCode window for the env to take effect there.

    How to use this tab: click Refresh to pull the live model list from the provider (uses GET /v1/models, or Ollama's /api/tags). Then pick the main model and a smaller/faster one for Claude Code's "small fast" slot. The dropdown is also a free-text input — type any model id the provider serves.

    Extra HTTP headers added to every request to the upstream provider. Common ones:
    • HTTP-Referer + X-Title — required by OpenRouter for proper attribution
    • accept: application/json — required by some NVIDIA NIMs endpoints
    • custom X-… headers your enterprise gateway requires
    Power-user knobs. System prompt prefix/suffix is bolted onto the system message before forwarding (handy for jailbreak prompts or persona text). Pass cache_control only matters on providers that support Anthropic's prompt-cache markers.
